# Graph Linker

当前 HTML 原型 v0.3：赛程 `.csem` v3 与只读战队资料 `.tinf` v1 分离。完整字段、识别码、ID 绑定及 C++ 接入约定见 [TEAM_INFO_FORMAT.md](TEAM_INFO_FORMAT.md)。

## 关于本项目

这是关于 CSEMTV 项目中，任意赛制流程链接器的概念开发分仓库。

## 基本设想

### 文件类型

赛制使用 `.csem`，战队资料使用 `.tinf`；两者均为独立识别码 + gzip 压缩 JSON。赛程只保存战队 ID 引用，战队名称、属性和排序输入由 `.tinf` 提供，编辑器不修改战队资料。

### 赛制流程的编码与编辑，以及任意赛制流程链接器（Graph Linker）的细节

一般来说，赛制流程由如下几个部分组成：单一比赛框，框间链接通道，种子层，起始层，赛果层，以及**阶段**的概念。

#### 框间链接通道

单一比赛框/种子层/赛果层 之间的通信通道，同一根管道一般用于传输单个队伍，但也可以传输空值和临时的双队信息。

#### 单一比赛框

单一比赛框包含两个**对阵位**，一个**通道接入口**，两个**通道接出口**和一个**比赛时序**。同时，比赛前后单一比赛框也有**未定/胜负 展示**和其余**比赛信息**。

- 对阵位：一场比赛必定包含且仅包含比赛双方，两支队伍各占一个对阵位。在本项目的构建中，对阵位按上下排列，先上后下。
- 通道接入口：用于读取从通道传来的队伍。一个通道接入口将接入两个通道，即允许接入两次队伍信息。队伍无先后，单一比赛框通过通道接入口接收的队伍将优先排入上对阵位，若上对阵位已满，则排入下对阵位。
- 通道接出口：用于通过通道发送队伍。一个通道接出口仅接出一个通道，单个通道仅允许且必须接出一次队伍信息。在该单一比赛框对应的比赛结束之后，即通过通道接出口发送两支队伍。两个通道接出口分为胜接出口与败接出口，对阵的胜方通过胜接出口发送至下一个单一比赛框或赛果层，对阵的败方通过败接出口发送至下一个单一比赛框或赛果层。
- 比赛时序：决定了本场比赛的比赛时间，写于右上角，格式为 YYYY-MM-DD #X。其作用和生成方式将于主项目中完善，此处占位即可。
- 其余比赛信息：和比赛时序相同，其生成方式将于主项目中完善，此处无需占位。
- 未定/胜负 展示：指三种不同的对阵位底色，初始为深蓝/正红/淡墨绿 表示胜负未定/败方/胜方，主项目中此处将允许更改，但此项目不需要考虑，但也需要留出接口。

#### 种子层，起始层与赛果层

三个特殊的比赛框，且赛事模拟过程中种子层和起始层均不显示。

- 种子层：包含了**全阶段**的所有比赛战队，按照某个方式排序并按顺序赋予**种子排名**，排序方式同样将在主项目中补齐，但是此处需要留出排序函数的接口，本项目中排序函数使用直接返回函数即可。
- 赛果层：包含了**本阶段**的所有比赛战队，每个战队位置包含一个通道接入口和一个通道接出口。赛果层分为两个区域：
  - 下阶段推送部分：进入本区域的队伍将被赋予**不为零的**的**阶段末排名**（注意，种子层中所有战队初始时的阶段末排名为零），用于下阶段的起始层排序，同时所有队通过每队各一根通道发送至下一阶段的起始层。
  - 结算部分：进入本区域的队伍将获得其在**本赛事**的**最终排名**，同时也将不被通道发送至下一阶段，即战队淘汰。
  - **当且仅当**当前阶段已是最后阶段时，本阶段赛果层的下阶段推送部分大小为零。在赛事模拟的过程中，也可根据当前阶段的下阶段推送部分大小是否为零来判断当前阶段是否为最后阶段。
- 起始层：包含了**本阶段**的所有比赛战队，从种子层和上一阶段的赛果层（第一个阶段起始层所有战队均来自种子层）接受战队直至填满预计的 X 支战队之后，排序并通过通道发送至后续的单一比赛框/赛果层。假设本阶段战队数为 X，则种子层包含 X 个不同的通道接出口，接至赛果层/单一比赛框。排序方式同样将在主项目中补齐，但是此处需要留出排序函数的接口，本项目中排序函数使用直接返回函数即可。同时，对于排序函数，该函数应当由玩家设定，程序提供第一/第二/第三关键字（玩家从种子排名、阶段末排名、**实时积分**排名三项中选择任意项，三个关键字均可空选，此时表示直接返回函数。同时，本项目中所有战队实时积分默认为0）

#### 阶段

完整的赛制流程被允许拆分为多个阶段，类似分p展示的逻辑。

### 其他细节

- TBD 填充：若单一比赛框/起始层/赛果层 中的对阵位/战队位值为空值，则显示为TBD。
- 双选预推送：单一比赛框对阵位填满且比赛开始前，向两个胜败发送通道均打包发送两支战队（假设是 A vs B）并附带特殊标记。在单一比赛框/赛果层中，若某一对阵位/战队位仅接收到一个带有特殊标记的信息，则解包该信息并将本对阵位/战队位显示为 ``A/B``。
- 按步推进：在本项目中，按照类拓扑序排序比赛推进的顺序（比赛的胜负随机决定），每次步进只结束一场比赛。每次步进后，立即推送当前比赛的结果，并按顺序判定当前阶段赛果层是否填满、下阶段起始层是否填满，若填满，则立即发送战队并检测是否产生了新的两个对阵位填满的单一比赛框，并加入比赛队列。注意，双选预推送机制推送的包含双队的特殊标记信息显示**不代表**改对阵位已被填充。
- .csem 文件的结构和读取器同样需要设计。由于资源限制，本项目中使用 JavaScript+HTML展示和完善该设想，但是主项目采用C++作为开发语言，需要维护最终态转C++的操作文档。


## 可运行 HTML 原型（2026-10-07）

打开 [index.html](index.html)，或在本目录运行 `python -m http.server 8765 --bind 127.0.0.1` 后访问 `http://127.0.0.1:8765/`。无需安装 npm 依赖。

1. 先导入 [sample.tinf](sample.tinf)，再用默认 8 队两阶段示例，每次“下一步”只结束一场，观察 A/B 候选、确认结果及跨阶段排序；可退回一步或重置。已确认的比赛进入 FIFO 队列，新就绪比赛追加到队尾；仅同一步同时就绪时按节点顺序破同序，不允许后来就绪的早建节点插队。
2. 点击阶段、比赛或赛果编辑属性；种子战队仅查看只读信息。出口再入口建立通道，Shift + 点击可增选/取消多个出口，再一次接入同一个入口。整批校验容量、方向、所属阶段与环路，非法时不写入部分通道。切换阶段保留出口选择，Esc 取消。
3. 创建下一阶段后，上一阶段的全部推送位自动接至新阶段起始层；已有下一阶段时，把赛果位改为推送也会自动接线。原有有效通道不会重复生成；改变为淘汰结算会移除该出口。目标人数不匹配时由校验提示，不静默丢弃晋级队伍。
4. 新比赛、赛果、大框和仅标签大框均生成在**当前可见画布的右上角**，按滚动位置和缩放计算，不按节点数量偏移。起始层标题也可拖动。网格为 23.5px（235px 框宽的 1/10）；单框拖动绝对坐标吸附，多框以首个选中框吸附并保留相对位置。连续新增允许重叠。
5. “模拟视图”隐藏种子和起始层。新建空白流程后导入 `.tinf` 提供战队 ID 引用，再按需增加阶段、比赛与赛果，校验通过才能推进。没有匹配战队时禁止演算。
6. 导入/导出带识别码、gzip 压缩的 `.csem` v3；只保存图与战队 ID。通过左侧“导入 .tinf 战队信息”载入只读资料。两个文件可按任意顺序导入；缺失 ID 逐项提示，选错用途明确报错且保留当前文档、战队库与演算进度。后缀改名不能绕过识别码校验。旧压缩 `.csem` v1/v2 可读取图结构，但内置战队数据不覆盖 `.tinf`。裸 JSON 外部文件仍拒绝。
7. 旧浏览器草稿只读迁移；新草稿的赛程与战队缓存分开存储，不覆盖旧草稿键。结构导入重置演算，编辑撤销可恢复此前战队库、图和演算。运行历史不写入赛程文件。

本轮实际通过 engine/editor/features/UI/team_info 五组共 **356 项断言**。已将用户当前 Copenhagen 存档拆分为 [Cphg2024.tinf](Cphg2024.tinf) 与 [Cphg2024.csem](Cphg2024.csem)，保留 24 队、73 场、40 赛果、34 框、226 通道及所有原排名。新增主工程属性在源存档中未知，写 null；没有填入 2026 默认库资料。浏览器实测两种导入顺序、用途错配、只读属性，并实际完成全部 73 场。完整记录见 [OPERATIONS_HANDOFF.md](OPERATIONS_HANDOFF.md)。

## 大框与画布操作（prompt.md 本轮实现）

- “新建大框”可拖入同阶段同类比赛/推送赛果/淘汰赛果；起始层不能入框。大框一个共享入口，容量为比赛数 × 2 或赛果数 × 1；小框出口保持独立。全部确认输入收齐后才分配队伍，候选 A/B 不计数。比赛按本阶段唯一 startRank 使用顺序、上下交错、首尾结合三种配对。自导入代码仅为占位，选择该项会阻止模拟。
- 小框由上至下紧密排列；标签在检查器编辑，顶部加粗居中。空框高 2 格；有成员时上下各留 1 格。逻辑宽 10 格，外观为圆角四边形，左右边框各延伸 1/5 格。拖出或“移出大框”解除归属；共享输入按成员位置和通道存储顺序拆回，保留独立出口，结构变化重置模拟。
- “新建大框（仅标签）”只辅助排列和标记。比赛入口、算法与比赛设置、赛果排名均独立；推送和淘汰赛果可在同一个仅标签框内排列。创建、拖入和标签合并保留已有演算，空标签框不阻止推进。
- 赛果大框内队伍并列，输入区间左端 L，显示并占用 `L～L+N-1`，成员的实际排名同为 L。并列必须合并为真实大框。每阶段推送区间须不重且覆盖 `1～晋级人数`；全部阶段最终排名须不重且覆盖 `1～全赛事种子人数`。仅标签框不能豁免重复排名。
- 右键拖动区域框选；空白画布左键拖动也可框选。只加入完全在区域内的元素，排除起始层和种子→起始层通道；包含大框时成员按整体选择。右键菜单或批量检查器可合并同类小框、转换混合赛果、复制、剪切、删除。真实赛果大框中一个成员改类型时整框同步，保证共享入口类型一致。Shift 点击框可增减选，拖动任一已选框可整体移动。
- Ctrl+C/X 将对象写入**程序内部缓存**，不读写系统剪贴板。复制类型、相对位置和所选子图的内部通道；名称、排名、BO、标签与算法等设置采用新对象默认值。Ctrl+V 只在鼠标悬停画布时粘贴，最小覆盖矩形中心对齐鼠标再吸附网格；画布右键菜单也提供粘贴。外部连线不克隆，孤立通道粘贴仍校验已有出口、容量、阶段和环路。
- Del/Backspace 删除单个或批量对象及附着通道。Ctrl+Z/Y 撤销/重做最近 40 项编辑；新编辑清空重做分支。布局撤销保留模拟状态，结构编辑重置模拟，撤销结构可恢复编辑前的模拟快照。输入框/下拉框/可编辑文本保留原生文本快捷键。

[group_demo.csem](group_demo.csem) 配合 [group_demo.tinf](group_demo.tinf) 为六队三场配对示例；[group_fifo.csem](group_fifo.csem) 配合 [group_fifo.tinf](group_fifo.tinf) 为部分输入已到达、整框收齐后入队的回归赛制。生成示例可执行 `node prepare_fixtures.js`，不读取或修改浏览器草稿。
